Security & reliability hardening

The interesting work is at the boundaries.

Hardening focused on failure modes that do not show up in a happy-path demo.

01

Tenant-safe nested resources

Every collection and endpoint operation proves the child belongs to the parent organization instead of trusting IDs embedded in a REST path.

RBACIsolation403 boundaries
02

Outbound request containment

HTTP(S)-only validation, all-current-DNS-answer checks, blocked private/reserved targets, no redirects, bounded timeouts, and a 1 MiB response capture limit.

SSRFTimeoutsMemory bound
03

Dependency failure isolation

A Resilience4j circuit wraps only the remote network operation so caller errors, RBAC failures, and SSRF rejections do not contaminate dependency health.

CLOSEDOPENHALF_OPEN
04

Kafka backlog recovery

The audit consumer owns its database independently. When the consumer is unavailable, Kafka retains the backlog and consumption resumes from committed offsets.

KafkaOffsetsFailure recovery
05

Safer deployment boundary

Nginx is the only all-interface Compose ingress. Direct app, broker, database debug, and monitoring ports are localhost-bound or private.

NginxComposeLeast exposure

Engineering judgment

What I would build next.

  1. Async execution workers: move outbound calls off servlet threads into queued execution jobs with backpressure and cancellation.
  2. Transactional outbox + idempotent consumer: close the DB/Kafka dual-write gap and guarantee one business effect under redelivery.
  3. Encrypted environment secrets: separate saved credentials from endpoint definitions, mask them, rotate them, and never return them by default.
  4. Session hardening: replace the current browser localStorage JWT model with a hardened short-lived/session strategy.
  5. Network-enforced egress policy: make private/metadata networks unreachable even if DNS changes after application preflight.
